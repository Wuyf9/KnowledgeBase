# .NET 后端配置、依赖注入与异步生命周期

状态：官方资料支持的通用参考，重点对应历史高频主题；未把任何机器人控制代码或未验证重构写入本篇。示例以现代 .NET 宿主为语境，迁移时核对实际目标框架和包版本。

## Program.cs 的检查顺序

先配置来源与必填项，再注册服务及生命周期，最后配置中间件和运行宿主。排查时记录实际环境名、内容根目录、运行时版本和非敏感配置摘要，不输出整个连接字符串。

- `GetSection` 返回配置节；标量使用 `GetValue<T>`，一组相关参数绑定 Options。
- 必填配置应在启动阶段验证；空 IP、错误端口、缺失路径不应拖到后台循环里持续报错。
- 默认宿主通常读取 appsettings 及环境专用文件，再由环境变量 / 命令行等覆盖；自定义提供器会改变优先级，要查看实际构建顺序。
- `IOptions<T>`、`IOptionsSnapshot<T>`、`IOptionsMonitor<T>` 的生命周期和刷新语义不同。修改文件不保证运行中的单例自动获得新值。

## DI 生命周期

| 生命周期 | 使用边界 |
| --- | --- |
| Transient | 每次解析创建；仍需明确释放归属 |
| Scoped | 同一作用域共享，Web 请求通常有独立作用域 |
| Singleton | 容器中长期共享，内部状态须支持并发 |

接口调用哪个实现，检查最终注册和解析方式；单个服务解析与 `IEnumerable<T>` 行为不同，也要检查条件注册及重复注册。不要把从根容器解析出来的 Scoped 对象保存到全局字段。

通过 AddHostedService 注册的 BackgroundService 是单例；处理一批工作时创建作用域，在作用域内解析 Scoped 服务，等待工作完成再释放。[Microsoft BackgroundService 作用域](https://learn.microsoft.com/en-us/dotnet/core/extensions/scoped-service)

DbContext 的并发和创建方式只维护在 [[02_Technology/MySQL/MySQL与EF-Core连接及数据操作]]。

## 取消、锁与释放

取消是请求，不是强制终止。把 token 传给实际异步 IO 和等待；分清应用停止、用户取消、单次超时。示例为局部代码片段：

```csharp
using var timeout = CancellationTokenSource.CreateLinkedTokenSource(stoppingToken);
timeout.CancelAfter(TimeSpan.FromSeconds(10));

await gate.WaitAsync(timeout.Token);
try
{
    await ProcessAsync(timeout.Token);
}
finally
{
    gate.Release();
}
```

只有成功取得 semaphore 后才进入 try/finally，避免未取得锁却 Release。此片段要求 gate、ProcessAsync、stoppingToken 已由调用方定义，并不代表完整可运行程序。

停止流程：停止新工作 → 请求取消 → 等待相关任务结束 → 释放 CTS、锁和 IO 资源。Dispose 不等于 Cancel；不要在任务仍使用 CTS 或 semaphore 时释放它们。长时间 IO 不应占住负责全部生命周期的锁，避免停止路径互相等待。

## HTTP 与日志

异步路径尽量贯穿 await，不用 Result / Wait 阻塞请求线程。HttpClient 采用合理复用或 IHttpClientFactory，区分每次尝试与整个操作的超时预算。重试与幂等性统一见 [[02_Technology/Network/网络与代理分层排查]]。

ILogger 是日志抽象，Serilog 等是具体日志方案，注册方式核对所用版本。日志应记录异常对象、事件、操作标识和耗时；正常停止导致的取消不应反复写 Error。记录“开始”“成功”分别对应真实阶段，不在异常后继续输出成功。

## 验收

分别验证缺配置启动失败、正常处理、处理中取消、服务停止、并发任务和依赖故障。对 ObjectDisposedException 记录资源所有者及释放时序，不用 catch 后忽略代替生命周期修复。
