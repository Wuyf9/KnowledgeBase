# 网络、HTTP 与反向代理分层排查

状态：通用参考；YARP 基本代理在「Yarp.ReverseProxy 介绍」中由用户确认已使用，主备与重试尚无落地回执。

## 按层缩小范围

| 层次 | Windows | Linux | 判断 |
| --- | --- | --- | --- |
| 本机地址 / 路由 | `ipconfig`、`route print` | `ip -br addr`、`ip route` | 当前机器有什么地址，去目标走哪条路 |
| DNS | `Resolve-DnsName example.com` | `getent ahosts example.com` | 域名是否解析到预期地址 |
| 目标 TCP | `Test-NetConnection example.com -Port 443` | 对 HTTP 服务用下方 curl | 成功仅说明该端口可建立连接 |
| 服务端监听 | `Get-NetTCPConnection -State Listen` | `sudo ss -lntp` | 在目标服务器检查绑定地址与端口 |
| HTTP / TLS | `curl.exe` | `curl` | 区分握手、状态码与业务响应 |

```bash
curl -v --connect-timeout 3 --max-time 10 https://example.com/health
```

此 URL 是格式示例，不是用户健康服务。替换为真实目标。分享 verbose 输出前清理认证头、查询令牌及业务信息。

- Ping 成功不证明 TCP 服务或已有连接正常；Ping 失败也可能只是 ICMP 被禁。
- Connection refused：常见于无监听或主动拒绝。连接超时：排查路由、过滤、目标状态；不能仅凭超时认定防火墙。
- 已收到 HTTP 401 / 403 / 404 / 500：说明至少到达某个 HTTP 响应方，继续核对代理与应用日志。
- TLS 错误先核对域名、证书链、时钟；不要默认永久关闭证书验证。
- 127.0.0.1 只指向发起请求的机器或网络命名空间；容器里的 localhost 不会自动指向宿主机数据库。

## 监听地址与客户端访问地址

127.0.0.1 只允许本机回环；0.0.0.0 是服务器 IPv4 全接口绑定通配地址，不是发给远端客户端的访问地址。客户端使用服务器实际 IP 或域名。

若 Kestrel 在 Socket.Bind 报地址无效，先核对该 IP 是否属于当前主机；端口占用则检查占用进程。需要外部访问时才扩大监听范围，同时核对访问控制。服务命令见 [[04_Troubleshooting/Linux/systemd服务管理]]。

## YARP：路由、健康检查和故障转移

Route 决定匹配请求，Cluster 指向后端集合，Destination 是一个后端地址。要仅让某个接口使用另一组后端，为它定义明确路径的 Route 和独立 Cluster；同时核对路由重叠、优先级、路径变换和鉴权。

健康检查可将不健康后端从可用集合排除，影响后续选择；它不保证当前失败的请求自动重新发送。RoundRobin 等均衡策略也不等同于严格“主节点优先、备用兜底”。[YARP 健康检查](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/yarp/dests-health-checks?view=aspnetcore-10.0)

验证主备时分别测试：主节点正常、停主节点、恢复主节点、两个节点全失败、仅指定路由受影响。检查配置的全失败策略，不能假定自动得到期望状态码。

如需重试同一次请求，还需解决请求体可重放、总超时预算、客户端断开、响应已开始和业务幂等性。特别是 POST 超时可能已被后端执行，不能盲目转到另一 IP 再执行一遍。

## 代理后的真实 IP、协议与 Swagger

ASP.NET Core 根据可信代理范围处理 Forwarded Headers。只信任已知代理 / 网络，按实际代理层数配置，且在依赖真实协议、重定向等组件之前处理；不要无条件信任客户端提交的 X-Forwarded-For。[Microsoft 代理配置](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-8.0)

Swagger 页面与 OpenAPI JSON 是两条请求。页面开得了但定义加载失败时，在浏览器核对 JSON URL、代理路径前缀、鉴权和状态码。先排除环境开关未启用，再处理转发，避免只修改 UI 路径。
