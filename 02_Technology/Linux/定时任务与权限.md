# Linux 定时任务、执行身份与权限

状态：通用参考；历史提出每日 1 点、每小时执行及 root 身份确认，尚无任务实际触发成功的回执。适用于 cron 已安装并运行的 Linux 主机。

## 时间表达式

用户 crontab 为“五个时间字段 + 命令”，依次是分、时、日、月、星期：

| 表达式 | 时间 |
| --- | --- |
| `0 1 * * *` | 每天 01:00 |
| `0 * * * *` | 每小时整点 |
| `*/10 * * * *` | 每小时第 0、10、20、30、40、50 分钟 |

每小时整点不是“安装后每隔一小时”。时区以 cron 实现和主机配置为准；普通 cron 不会自动唤醒关机或休眠的电脑，也不保证补跑错过的任务。

## 身份与路径

`crontab -e` 编辑当前用户任务；`sudo crontab -e` 编辑 root 任务。用 `sudo crontab -l` 核对 root 的最终内容。在 root 环境里 `~` 指向 root 的家目录，不是原登录用户目录。

```cron
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
0 * * * * /usr/local/sbin/example-maintenance.sh >> /var/log/example-maintenance.log 2>&1
```

上例放在 root 的用户 crontab，无用户名列；若改为 `/etc/cron.d/example-maintenance` 则在时间后增加 `root`。使用绝对路径，并先确保脚本和日志目录存在。

`>>` 追加标准输出，`2>&1` 再把错误合到当前标准输出。交互终端定义的 `SCRIPT_PATH` 不一定在 cron 中存在；安装脚本应写入已经展开的绝对路径，不能只把变量名原样复制进去。

## 可重复安装与修改

- 保留其他任务，不用一份新 crontab 覆盖全表。
- 手工修改现有同主题行，或用单独的 `/etc/cron.d/` 文件作为唯一维护位置；不要两处同时安装。
- “搜索到脚本路径就跳过”会导致旧时间永远不更新。安装器应对比完整期望配置，路径相同而时间改变时更新已有任务。
- root 执行的脚本及父目录不能让普通用户随意写入。推荐 root 管理代码，按所需权限设置如 0750 / 0755；没有理由统一授予 0777。
- 长任务可能与下一轮重叠，可使用发行版提供的 `flock` 做互斥，并约定跳过重叠运行时如何记录；锁文件目录要有权限。

## 验收和回滚

先以计划执行账户手工运行维护脚本，确认退出码与输出；再核对最终 cron 配置、系统时区、cron 服务状态。至少观察一次实际计划触发时间和日志，才标记部署成功。日志配置轮转，避免无限增长。

回滚仅删除本次新增条目或独立配置文件，恢复此前时间，不删除整张 crontab。服务日志入口见 [[04_Troubleshooting/Linux/systemd服务管理]]；发布流程见 [[02_Technology/Deployment/服务部署与脚本维护]]。
