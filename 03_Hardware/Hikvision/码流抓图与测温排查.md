# 海康码流、ISAPI 抓图与测温显示

状态：用户提供的通道 XML 已读取；抓图及测温显示问题尚无完整修复回执。能力以具体型号、固件和设备返回为准。

## 已知通道与通用规则

「主码流与子码流作用」附件是 StreamingChannelList。本次读取并核对其流 ID 与 videoInputChannelID，不把历史截图推测当设备通用结论。

| 流 ID | 物理输入 | 含义 |
| --- | --- | --- |
| 101 | 1 | 第一输入主码流 |
| 102 | 1 | 第一输入子码流 |
| 201 | 2 | 第二输入主码流 |
| 202 | 2 | 第二输入子码流 |

这份历史设备被用户描述为双光谱设备，第二输入用于热成像。不能推广为“所有海康通道 2 都是热成像”。主码流常用于画质优先，子码流常用于预览和带宽控制，实际分辨率、编码、帧率读取设备配置。

## 先查询，再抓图

先查询支持列表：

```http
GET /ISAPI/Streaming/channels
```

然后用设备返回的流 ID 调用：

```http
GET /ISAPI/Streaming/channels/201/picture
Accept: image/jpeg
```

201 是此案例第二输入主流示例；不要把物理通道号 2 与码流 ID 201 当作同一命名空间，也不能断言所有固件的 /2/picture 都无效。

如果响应以 `WWW-Authenticate: Digest` 质询，使用支持 Digest 的客户端。Windows 示例会交互提示密码，避免把密码放进命令文本：

```powershell
curl.exe --digest --user camera-user --connect-timeout 3 --max-time 10 --fail -D response-headers.txt -o snapshot.jpg "http://192.0.2.10/ISAPI/Streaming/channels/201/picture"
```

192.0.2.10 是示例地址，替换目标；协议 / 端口按设备配置。有 HTTPS 能力时正确配置证书。核对最终 HTTP 状态、Content-Type，并实际打开图片；生成 jpg 文件不证明里面不是错误内容。[curl 官方选项](https://curl.se/docs/manpage.html)

RTSP 的常见格式为 `rtsp://设备地址:554/Streaming/channels/201`，在客户端凭据设置中认证。RTSP 会话能建成仍要检查解码、连续帧和丢帧情况。

## 抓图无温度与预览温度消失是两个问题

1. **JPEG 没有温度文字**：可能是客户端根据独立元数据绘制，普通图像没有合成该层；也可能受设备叠加设置影响。需比较网页、RTSP 解码帧、JPEG 及配置，不能直接认定固定根因。
2. **发起抓图后，原本预览的温度消失**：记录抓图前后配置、是否只在某客户端发生、重新打开预览是否恢复，以及固件版本。单纯 GET 的设计用途是读取，但不能排除具体设备缺陷或另一个程序同时修改配置。

历史提出获取测温元数据再自行绘制，是待验证方案。热成像接口使用的物理通道与 Streaming 接口的流 ID 分开核对；未确认型号能力前不照抄特殊测温接口。附加温度数据也不等于文字已经绘入 JPEG。

## 最小验证流程

一次只开一个客户端，以低频单次抓图测试。记录所用流 ID、HTTP 最终状态、图像能否打开、预览是否受影响；随后再增加 RTSP 客户端比较。读取 OpenCV 的 FPS / 尺寸仅查询本地流属性，不等于写设备配置，但整个程序是否有设置请求仍须检查。

验收应包括所需温度信息确实显示且预览稳定，不能用“成功下载图片”替代测温验收。
